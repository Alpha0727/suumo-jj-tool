# SUUMO JJ 上位版：送信取り違え防止の模擬検証（2026-10-25）

## 適用範囲
- 検証用ブランチのみ。`dev` / `main` の公開版へは未反映。
- 対象：`SUUMO-DEV.user.js`。バージョン表記は検証中の `7.54.11`。
- 実際のSUUMOへの送信・いえらぶのデータ更新は **実行していない**。

## 不具合と対策

### P0-A：戻る・進むで旧確認画面が現在の物件として送信される
- 履歴エントリごとに `ownerToken / index / url / itemId / kind / entryId` を記録する実装を確認。
- `sessionStorage` の最新対象と `history.state` の不可変な履歴エントリを照合。
- 画面復帰しても古いエントリのIDが現在の対象に一致しなければ送信を拒否。
- 250ms の最終送信待機後および排他ロック内でも対象を再照合。

### P0-B：前物件の遅延完了が次物件の完了として記録される
- HTTP POST の結果が未確認になった場合、**次の掲載への自動進行を廃止**。
- ステージを `send-uncertain` にして自動送信を停止し、送信IDと最終送信ガードを保持。
- 現タブに隔離フラグを保存。中止後に同じタブで新しい一括処理を開始できない。
- 同じ物件・同じ送信ID・同じ履歴経路の遅延完了だけを確認できた場合、完了扱いにして隔離解除。
- 完了が確認できないときは二重送信をせず、SUUMOの受信結果を人間が確認。
- 結果未確認中はパネルの再送信・スキップを行えない状態にする。

## 模擬テスト
接続済みGitHubの最新ソースから、安全関連の **実際の関数定義を抽出** し、ブラウザAPI／履歴／GMストレージ／クリックをモックして実行。

### 履歴・POST・完了（17件合格）
1. A掲載画面の初期紐付け
2. A入力画面への紐付け
3. A確認画面への紐付け
4. B掲載画面への紐付け
5. B入力画面への紐付け
6. B確認画面への紐付け
7. B送信直前の対象識別取得
8. Aの古い確認画面へ戻る操作で送信対象の検証が失敗する
9. B確認画面へ進む操作で正しい対象へ戻る
10. Aの送信対象再準備
11. POST識別情報の照合
12. POST結果不明で次の番号に進まない
13. POSTのガード情報を保持する
14. タイムアウト重複通知を増やさない
15. 旧送信IDの完了画面を拒否する
16. 同じPOST IDの遅延完了を認める
17. 正当な遅延完了後に完了処理を進め、誤った未確認記録を取り消す

### 最終送信ボタンクリックの模擬（4件合格）
1. 実際の `handleConfirmPage()` で、非同期待機中の旧履歴へ戻るとクリックしない
2. 上記の状態で送信ガードを書き込まない
3. 正しい確認画面ではモック送信ボタンを1回だけクリック
4. 送信ガードと完了遷移チケットが同じ掲載インデックスを指す


### タブ隔離・UI・構文（8件合格）
1. 未確認送信がある同一タブで新しい一括処理を開始しない
2. 停止されたタブでプロフィール確認処理に進まない
3. 停止されたタブで次の物件のタブ識別情報を作成しない
4. 未確認フラグのないタブは通常の新規処理を開始できる
5. 未確認判定時にタブ隔離フラグを保存する
6. 同じ物件・送信IDの完了確認時に隔離を解除する
7. 結果不明時に再試行・スキップボタンが有効にならない
8. スクリプト全体が JavaScript として構文解析できる

合計 **29件の模擬・静的検証に合格**。これらは実ブラウザ検証の代替ではありません。

## 今回の限界
- テストはブラウザとSUUMOページの模擬。Chrome上の実ページ・実通信を使った再現試験ではない。
- ページ遷移の方式、BFCache、SUUMO側の完了レスポンスの実際のタイミングは未検証。
- 結果未確認で一旦止める安全策のため、従来の「結果不明でも次へ自動進行」とは動作が変わる。
- 未確認送信がある場合は元の申告タブを保持し、受信状況を確認する。追加修正後は共有ガードが残る間、別タブからも新しい一括処理を開始しない。詳細は末尾の追加修正報告を参照。

## 公開判断
**実運用への公開は保留。** 実サイトで誤クリックしないことを含む慎重な再現テストが必要。
