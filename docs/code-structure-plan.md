# SUUMO JJ 上位版：コード構成見直し案（Ver.7.54.9時点）

## 現状
- 配布コード：`dev/SUUMO-DEV.user.js`（Tampermonkey向け約3,000行の単一ファイル）。
- 機能：いえらぶ側の取得・編集、SUUMO検索の一覧解析、物件照合、会社別選択、一括申告、確認画面・送信、安全停止・復旧、設定・UI、GitHub更新。
- 共通の保存キー（GM storage）・画面ごとの状態・相互呼び出しがあるため、単純に行数でファイル分割すると依存関係や送信状態が壊れる可能性がある。
- 2026-10-24の7.54.9では送信確認のみ局所改修。配布方式や保存データの形式は変更しない。

## なぜ配布用は1ファイルを維持するか
- Tampermonkeyの既存インストールと更新URLを変更せずに済む。
- `@namespace`、`@match`、`@grant`、`@connect`をまとめて管理できる。
- 外部複数ファイルの読み込み増加やバージョン不整合を避けられる。
- 開発時だけモジュール化して、ビルドで1本に結合する（例：esbuild等）。**ただし現時点ではビルド環境を導入していない。**

## 優先して整理する順序
1. **既存動作のテスト固定**：模擬検索・会社選択・フォーム入力・送信状態・二重送信防止。ユーザー操作や実サイト送信はテストで実行しない。
2. **定数と保存データキーの一覧化**：旧保存値との互換性を固定。データ移行は別途検討。
3. **検索部分を抽出**：SUUMO一覧読取・住戸照合・会社別集計。入力/出力が明確でモック化しやすい。
4. **いえらぶ連携とUIを分離**：共通状態を明示的に受け渡す。
5. **最後に送信状態機械を分離**：最も事故リスクが高く、正常／失敗／復帰の回帰テストを整えてから移行する。
6. **単一配布ファイル生成を自動化**：ビルド結果とコミット・リリース版の一致を検査する。

## 注意事項
- フォルダー分割だけでは実行時間は原則速くならない。目的は保守性、バグ修正、安全性、テスト容易性。
- 単なるファイル分割と高速化・送信動作変更を一度に行わず、変更原因を追える単位で段階リリースする。
- 配布URL `dev/SUUMO-DEV.user.js`、一般版 `main`、独立のIERABU-SPOTは変更しない。
- SUUMO本来の確認ページ、最終送信前ガード、送信結果が不明な場合の二重送信防止は最終段階まで維持。
- Ver.7.54.9の送信フローは関数単位の模擬試験を行ったが、ログイン済みSUUMO実環境では未検証。
