# Ver.7.54.8 高速化・検証レポート

## 基準・対象

- 基準：dev `15d9d53e0b7e64c6a14f1a5efdfde3ac4e98a4dc`、Ver.7.54.7。
- 対象：上位版のみ。main、一般版8.0、IERABU-SPOTは変更しない。
- バックアップ：`backups/2026-10-24-before-7.54.8/` に本体と更新設定をバイト一致で保存。

## 調査結果と比較した方針

| 優先 | 原因・候補 | 判断 |
| --- | --- | --- |
| 1 | 通信・解析が終わるたび240msを追加待機 | 開始間隔240msへ変更。応答が遅い場合の二重待機を除去。取得は常に1本 |
| 2 | 会社リンクがあるカードも予備DOMを走査・正規化 | 予備処理を必要時だけ実行。取得する会社名の優先順位は維持 |
| 3 | 30件表示から100件表示 | 7.54.7ですでに100件指定。維持し、30件表示への互換性もテスト |
| 4 | ページの並列取得 | 今回は不採用。実サイトの制限・応答が未検証で、先読み通信やエラー時の不要通信が増える。開始間隔方式で負荷を抑えつつ短縮 |
| 5 | 物件ごとの画面遷移削減 | 今回は不採用。ページ依存のゼロ件判定、認証タブ・物件番号・再開状態との対応を保つため。検索画面ロードの負担は残る |
| 6 | HTMLを正規表現だけで抽出 | 不採用。会社リンク欠落やID不一致判定を維持するためDOMParserを残す |
| 7 | 長期HTMLキャッシュ | 不採用。掲載の鮮度を落とす。既存の同一引き継ぎ・同一検索URL・同一照合方式で完了した結果の再利用は維持 |
| 8 | 申告の待機短縮 | 不採用。自動確認2段階、最終送信250ms、完了100ms、次掲載150ms、失敗時500msの待機は維持 |

取得済みの現在ページは検索パラメーターが一致するときだけ再利用する。新たなHTMLキャッシュは設けない。会社別集計と掲載重複判定は既存のMapで行い、カードのセル取得時の不要な配列コピーと、バッチ開始時の同一状態3回保存も削減した。

## 修正前後の処理フロー

共通：いえらぶ一覧取得 → 詳細HTMLから所在階取得 → 編集・保存 → SUUMO検索画面へ移動 → 一覧全ページの住戸照合 → 会社別集計 → 次物件へ移動 → 全物件完了後に会社選択 → 選択した掲載の申告。

- 旧：各ページ照合 → **240ms固定待機** → 次ページ通信 → HTML解析 → 照合。
- 新：各ページ照合 → **前回の通信開始から240msに足りない分だけ待機** → 次ページ通信 → HTML解析 → 照合。
- 同時取得数：旧・新とも1。通信が300msなら、その通信時間を次の開始間隔に含める。
- 通信数：正常系では削減せず、全ページを読む。100件ちょうど等の満杯の最終ページで次リンクがない場合の確認通信も維持する。単に「次リンクがない」ことを理由に未確認結果を捨てない。
- 築年月は検索キーワードでのみ使用し、詳細ページを取得しない。住所・階数・面積・賃料の比較、号室を一致条件にしない仕様は維持。

## 実測結果

実際のChromiumブラウザで計測した**模擬データの結果**。SUUMO実サイトやユーザーのログイン済みブラウザでは計測していない。通信時間はテストで300msに設定したもので、実サイトの観測値ではない。

環境：Node.js 24.19.0、Chromium 154、Playwright、headless。旧・新とも同一HTML、301掲載（100+100+100+1）の4ページ、初回表示済み、追加通信3回。3回計測の中央値。

| 項目 | 7.54.7 | 7.54.8 | 結果 |
| --- | ---: | ---: | --- |
| 検索・照合・集計の全体 | 1651.6ms | 1158.9ms | 492.7ms、29.8%短縮 |
| 追加通信回数 | 3 | 3 | 同じ、全ページ確認 |
| ページ間の待機 | 指定値合計720ms | 計測値約235ms | 通信時間との重複を削減 |
| 取得HTMLのDOMParser処理 | 8.2ms | 8.1ms | 差は小さく、改善とは判断しない |
| 1000カード読み取り単体 | 29.5ms | 18.2ms | 11.3ms、38.3%短縮 |

1000カードの単体計測は、会社リンクと予備会社情報のdivを持つHTMLをウォームアップ後に5回処理した中央値。予備DOMの少ない実ページでは効果は小さくなる。HTML解析とカード読み取りは別の工程である。

30件表示では301掲載に11ページ（初回を除く追加通信10回）、100件表示では4ページ（追加通信3回）を要する。これは件数からの算出であり、30件表示301掲載の速度実測ではない。30件表示そのものの動作は31掲載・2ページで旧新版比較した。

1000カードのDOMと抽出結果を保持したメモリ計測も実行。GC後のV8使用量は旧約1.47MB／新約1.52MB、DOM等のembedderヒープは旧約8.99MB／新約7.23MBだった。1回の測定でGCやエンジンの揺らぎがあり、メモリ削減の保証には使わない。ピークのプロセスメモリ・長時間連続運転は未測定。全HTMLをキャッシュせず、ページ終了後にDOM参照を保持しない設計を維持し、循環検出は最大80ページ分のID文字列だけを保持する。

生データ：`tests/optimization-results.json`、`tests/memory-results.json`。機能・速度比較は `node tests/optimization.cjs`、メモリ計測は `node tests/memory.cjs`。再計測すると結果JSONを更新する。

## 検証

31項目に合格。模擬HTMLを使い、旧新版で物件ID（URL内）、会社キー・会社名・掲載URLと並び順を含む集計結果を深い比較で確認した。

- 0／1／30／100件、100件超、30件表示でのページ継続。
- 掲載ID重複、同じ建物の別号室、階数・面積・賃料・住所の不一致、異なる掲載会社。
- 会社リンクなしのテキスト会社名、面積欠落の除外、会社名欠落の停止、ID不一致・同一IDの会社不一致の停止。
- 次ページ欠落・重複ページの停止。
- 一時通信失敗からの復旧、繰り返す通信失敗、タイムアウト、403、429、長いRetry-After、非HTML応答。
- 取得中の引き継ぎトークン変更・対象番号変更・申告バッチ開始による停止。失敗時は部分結果を保存しない。
- 実ブラウザの模擬2物件連続ナビゲーション、全物件完了後の自動会社選択、再読み込みでの取得済み結果再利用、今回除外・永久除外の保存。
- 模擬申告フォームで物件情報の自動入力・不一致停止・2段階確認・送信連打抑止・送信結果不明状態の再送信抑止。送信リンクのクリックをローカルカウンターに置き換えている。
- 既存の保存キー・照合方式識別子・namespace・更新URLの一致。送信・自動入力等7関数のコードが旧版と同一であることも確認。
- 不明な最終空ページと非連続のページ循環の停止。

タイムアウトテストは12秒用のタイマーのみ40msに短縮してAbortSignal経路と最大3試行を確認した。実際の12秒を3回待つ計測ではない。

### 意図的な差異・復旧方針

- GET通信失敗・タイムアウト・HTTP 408/429/500/502/503/504は、最大3試行。750ms→1500msの待機を設ける。Retry-Afterがそれより長い場合は尊重し、60秒超なら自動再試行せず停止する。403や非HTML・不完全HTMLは再試行しない。申告POSTや送信クリックを再試行する変更ではない。
- 不明な空ページを最終ページ扱いしない。旧版が黙って完了する場合でも、明示的なゼロ件表示を確認できなければ停止する。実サイトの終端応答が別表記の場合は停止が増える可能性がある。
- 非連続のページ循環は即時停止する。現在の検索条件と違う表示ページを先頭ページとして使わない。取得途中に対象や実行状態が変わった場合は保存しない。
- 検証できた通常掲載で抽出結果の意図的な差異はない。

## 計測ログの見方

Chrome開発者ツールのConsoleでVerboseを有効にし、「性能」を絞り込む。

- `ielove-acquisition`：いえらぶ取得全体（完了件数付き）。
- `search-total`：1物件の検索全体。`requests`、`retries`、`networkMs`（通信・応答本文）、`parseMs`（DOMParser）、`matchMs`（カード読み取り・照合・ページリンク判定）、`waitMs`、`pageCount`。
- `company-grouping`：会社別の集計時間。
- `company-selection-dom`：会社選択画面のDOM構築時間。
- `report-form`：フォーム準備全体。既存の自動入力計測も維持。

既存の「工程」ログは画面をまたぐDate.now()の差分を最大100件保存する。`search-navigation-start`→`search-collect-start`はSUUMO移動・ロード・初期化、`all-properties-complete`→`company-selection-visible`は一覧構築から次の描画機会までを表す（画面ピクセルが表示済みという保証ではない）。ユーザーの編集・操作待ちをまたぐ差分には操作時間も含まれるため、通信時間と混同しない。細かい性能ログはコンソールのみで、掲載ごとの大量ログや毎カードのGM保存は行わない。

## 維持した機能・残る制約

既存UI、いえらぶ情報の編集・引き継ぎ、連続検索、住所等の照合、会社別一覧、今回／今後除外、申告対象選択、自動入力、進捗・再開・エラー復帰、GitHub自動更新、最終確認と送信動作を維持。一般版と別リポジトリは対象外。

Tampermonkey拡張そのもの、ログイン・Cookie・実サイトのHTML差異、実回線・混雑・アクセス制限、実データでの長時間動作は未検証。模擬テストはこれらを保証しない。検索キーワードの築年月はSUUMOの完全一致を保証しないという7.54.7の制約も残る。完了済み結果は従来どおり同一引き継ぎ内で再利用するため、長く中断した場合の掲載鮮度にも従来の制約がある。

次の改善は、利用者が実サイトで取得した工程ログと個人情報を除去した検索HTMLを基に、物件ごとの画面遷移を1タブ内通信へ置き換える方式と、全体で同時2件までの取得方式を比較すること。検索URL・物件番号・認証・停止制御・鮮度を一体で検証し、効果とサイト負荷の実測後に別更新とする。今回の結果を実サイトでの「最大速度」の証明とはしない。
