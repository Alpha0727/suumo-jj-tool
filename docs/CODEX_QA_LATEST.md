## 発見した問題と修正

### F1：P0 — 複製タブが同じ実行情報を引き継いで送信できる

開始コードで、確認画面を`window.open`してsessionStorageと所有トークンを複製し、旧履歴スタンプを与えて2タブを実行すると、0/100/400ms差の各ケースで送信クリック2回を再現した。Web Locksのクリティカルセクションだけでは、タブごとにコピーされた送信履歴を継続的に共有できない。旧キューを新しいタブで独立させる仕様も満たさない。

修正箇所：`discardOpenedTabRuntime()`（本体128行付近）、`init()`、`setBatch()`。ブラウザの`window.name`とタブ内識別子を照合し、新しい空のpopupにコピーされた実行状態だけを破棄する。プロフィール、恒久除外、いえらぶ引継ぎのGM保存は変更しない。同一タブのナビゲーションでは識別子を保持する。

再検証：0/100/400ms差の3ケースで旧バッチは新タブで非稼働、最終クリック合計1回。独立した2バッチの同時Web Locks要求も1クリック。同一タブの二重実行も1クリック。**意図的に新しいタブで新バッチを開始することは許可**し、元タブの送信不明保護は保持した。別タブの再申告を永続禁止する旧仕様には戻していない。

### F2：P1（誤送信防止上の問題）— 保存状態の破損・拒否で処理を継続

開始コードの`tabGet()`はJSON解析失敗や読み取り拒否をfallbackに置換していた。`ielove_suumo_execution_v1`を不正JSON、誤ったルート形状`{}`、当該キーだけ読み取り拒否とする各ケースで、申告データがない通常経路として扱われ、**模擬最終クリック1回**を再現した。実際に別物件を送信したという実証ではないが、「保存状態を確認できなければ送信しない」という仕様に違反する。

修正箇所：`failTabRuntime()` / `validTabRuntimeValue()` / `tabGet()` / `tabSet()` / `tabDelete()`（本体81行以降）、送信対象照合、検索処理。読取り・書込み・削除の失敗をタブ内にラッチし、型不整合も停止する。個人情報を含む破損値や例外本文をこの診断ログへ出さない。設定の削除・GMへのフォールバックを行わない。

再検証：上記3ケースと容量超過は0クリック・保存異常の表示。プロフィールと恒久設定を保持。壊れたactiveを持つ検索では候補保存・遷移とも0。全壊れ方を網羅した保証ではなく、テストで定義した形式とアクセス異常を確認した。

### F3：P2 — 未使用のBatchStateに旧GM参照が残存

`BatchState.get/set`（本体847行付近）が`GM_*(BATCH_KEYS[key])`を参照していた。現時点の呼出箇所はなく、これによる検索停止は未実証。将来の再利用で旧activeを読む経路になるため、`tabGet/tabSet`へ統一した。実アダプターを使う追加テストと静的検査に合格した。

### F4：修正中に追加発見・公開前に解消 — 履歴欠落を新タブと誤認

最初の修正案の「openerあり・履歴1件・スタンプなし」だけでは、同一タブの履歴識別が消えたリロード時に未確認送信のguardを消すケースが再現した。開始コードの新規不具合として数えていない。

`window.name`とタブ内識別子で区別する現在の修正に変更。同じタブは履歴スタンプがなくても送信記録・隔離マーカーを消さず、送信・再開始を拒否する。名前や識別が曖昧なら保存状態を残して停止する。`opened-tab reload with lost history cannot erase pending send` が、最初の修正案でFAIL、現在でPASS。

## 旧テストの更新理由

旧GM実行状態への注入・読取りをタブ保存へ移行した。新タブを永続guardで禁止する旧期待値は、明示された新仕様どおり「元タブを保護しつつ独立開始を許可」へ変更。

fast-reportのモックに`tabGet`、進捗DOMモックに`style`がなく初回4件失敗していたためモックを修正。optimization/memoryが削除済み7.54.8配布ファイルを読み込んで起動不能だった点も修正し、現在本体と8.0.2を読むよう変更した。検索再試行はページ単位でなく検索全体の3回なので実際のcollect関数で検証し、再試行時の1ページ目再取得も通信回数に含めた。

7.54.7との関数本文の完全同一性やnamespace一致は新仕様と両立しないため、現在の動作テスト・TEST隔離メタデータ検査へ置換。安全動作を旧テキスト一致で判定していない。ケースのskip、期待される誤クリックの許容、送信保護の無効化はしていない。生成JSONは/tmpへ出し、過去の追跡済み結果JSONを最新版として扱わない。
